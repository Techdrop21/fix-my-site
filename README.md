# fix-my-site

A single-page marketing site for an independent software engineer based in Nairobi offering website builds, repairs, and technical fixes to Kenyan businesses. Built with TanStack Start (SSR), React 19, Tailwind CSS v4, and deployed via Cloudflare (Nitro).

---

## What it does

The site is a direct-response landing page targeting small businesses that need:

- A new business website or landing page built fast
- An existing site repaired (broken forms, mobile issues, deployment problems)
- Technical web development work (Django, React, APIs, integrations)

Every call-to-action opens a pre-filled WhatsApp conversation with the developer.

## Page sections

The landing page (`src/routes/index.tsx`) is composed of these sections in order:

1. **Nav** — logo, service links, WhatsApp CTA button
2. **Hero** — headline, subheadline, primary CTA, trust signals
3. **TrustStrip** — industries served (construction, clinics, salons, etc.)
4. **Problem** — numbered list of common website problems
5. **Services** — six service cards (Business Sites, Landing Pages, Repairs, Deployment, Forms, Technical Fixes)
6. **Pricing** — three fixed-price tiers (Quick Fix KES 3k–5k, Starter Site KES 7.5k, Business Site KES 15k)
7. **Process** — three-step workflow (describe → quote → live)
8. **Why** — differentiators (direct developer, fast turnaround, fixed scope, practical solutions)
9. **Urgency** — dark section with primary WhatsApp CTA
10. **FinalCTA** — closing section
11. **Footer** — copyright, WhatsApp link

## WhatsApp integration

All CTAs link to `https://wa.me/<number>?text=<pre-filled message>`. The number is controlled by:

1. **Environment variable (preferred):** `VITE_WHATSAPP_NUMBER` — set in `.env.local`. Digits only or any format; non-digit characters are stripped automatically.
2. **Fallback hardcoded value:** `254717950959` (Kenyan number `0717950959` with country code).

Each pricing card passes a unique pre-filled message so the developer immediately knows which package the client is interested in.

## Getting started

**Prerequisites:** [Bun](https://bun.sh) installed.

```bash
# Install dependencies
bun install

# Start the development server
bun run dev
```

The dev server starts at `http://localhost:3000` by default.

---

## Environment variables

Create a `.env.local` file in the project root to override defaults:

```env
# Optional — override the contact WhatsApp number
# Accepts any format; non-digit characters are stripped
VITE_WHATSAPP_NUMBER=254717950959
```

All `VITE_` prefixed variables are injected into the client bundle at build time by Vite.

## Routing

Routes are file-based under `src/routes/`. TanStack Router's Vite plugin auto-generates `src/routeTree.gen.ts` on every change — do not edit that file manually.

| File | Route |
|---|---|
| `src/routes/__root.tsx` | Root layout (wraps all routes) |
| `src/routes/index.tsx` | `/` — the main landing page |

To add a new page, create a new `.tsx` file in `src/routes/`. See `src/routes/README.md` for naming conventions.

## Styling

The design uses Tailwind CSS v4 with a custom OKLCH color palette defined in `src/styles.css`. Key design decisions:

- Background: warm off-white `#fbfaf7`
- Accent color: emerald-500 for highlights and CTAs
- Typography: system font stack, tight tracking, neutral-900 base
- Layout: max-width `6xl` with consistent `px-5` gutters
- All components are mobile-first with `md:` breakpoint variations

Dark mode tokens are defined in `.dark` but the site does not currently toggle dark mode.

## Deployment

The project is configured for **Cloudflare Workers** via Nitro (set in `@lovable.dev/vite-tanstack-config`). The build output is a Cloudflare-compatible edge function.

```bash
bun run build
```

The SSR server entry (`src/server.ts`) wraps TanStack Start's server handler and normalises catastrophic SSR errors into a friendly error page rather than leaking raw h3 JSON responses.

This project is connected to [Lovable](https://lovable.dev). Commits pushed to the connected branch sync back to the Lovable editor automatically. Do not force-push, rebase, amend, or squash commits that are already pushed — doing so rewrites history on Lovable's side.

## Adding UI components

This project uses [shadcn/ui](https://ui.shadcn.com). Components are already copied into `src/components/ui/` and are not installed from npm — edit them directly if needed.

To add a new component, follow the shadcn/ui docs and copy the component source into `src/components/ui/`.
